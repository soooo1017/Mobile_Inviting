# 에디터(B9) 기획안 — 블록 에디터

> 상태: **초안 v2 (2026-10-12) · 검토 중**
> 범위: IA 7~8번 — 에디터 메인(B9), 블록 편집, 이미지, BGM, 미리보기. 확정된 결정과 아직 정할 것(§11)을 구분해 적었습니다.

## 1. 핵심 방향 (확정)

- **커스터마이징(블록 조립)이 기본 엔진**이고, **템플릿은 그 블록들을 미리 배치해 둔 시작점(프리셋)**.
- 템플릿을 별도로 개발하지 않음 → 블록 엔진만 잘 만들면 템플릿은 데이터로 계속 추가할 수 있음.
- **엔진과 기능을 먼저 완성하고, 템플릿은 그 엔진을 활용해 나중에 만든다** (템플릿 개수도 그때 결정).
- 같은 엔진을 **감사페이지 자유모드**에서도 그대로 재사용.
- PLANNING.md §3의 셀링포인트("템플릿을 고르는 게 아니라 블록으로 조립한다")는 그대로 유지. 템플릿은 빈 화면에서 시작하는 부담을 덜어주는 출발점 역할.

## 2. 편집 방식 (확정)

- 화면에는 **블록들이 세로로 쌓인 리스트** — **세로 배치만 지원** (좌우로 나란히 놓는 가로 배열은 MVP에서 제외, 필요해지면 나중에 추가)
- 블록을 **탭하면 그 블록 전용 편집 시트/화면**이 열림 (텍스트면 서식+내용, 이미지면 사진 선택 등)
- **길게 눌러 순서 변경**, 블록 사이 **`+`로 추가**
- 노션처럼 문서 안에서 바로 타이핑하는 인라인 편집은 하지 않음 — React Native에는 웹의 `contentEditable`이 없어 구현 난이도가 매우 높고, 모바일에서는 블록 단위 편집이 더 편함

## 3. 블록 목록 (확정 — 동영상 제외)

| 구분 | 블록 | 편집 항목 | 비고 |
|---|---|---|---|
| 기본 | 텍스트 | 서식(제목1·2·3 / 본문1·2), 내용, 정렬, 글꼴·색상 | |
| 기본 | 이미지 | 사진 1장, 비율·크롭 | |
| 기본 | 갤러리 | 사진 여러 장, 레이아웃(1열 / 2열 그리드 / 슬라이드) | PLANNING §10의 갤러리 레이아웃 변형 |
| 기본 | 구분선 | 모양(선 / 점 / 하트 등) | |
| 기본 | 여백 | 높이(작게 / 보통 / 크게) | |
| 기본 | 버튼(링크) | 문구, 연결할 주소 | |
| 연락·위치 | 지도 | 장소 | ⏸ **나중 작업** — 카카오/네이버 지도 API 결정 후 |
| 연락·위치 | 전화번호 | 이름, 번호 | 게스트가 탭하면 전화/문자 |
| 연락·위치 | 이메일 | 주소 | 게스트가 탭하면 메일 앱 |
| 기능 | 일시·D-day | B7에서 입력한 일시 자동 반영, D-day 표시 | 게스트용 "캘린더에 추가" 버튼 |
| 기능 | RSVP | 안내 문구, 받을 항목(참석 여부 / 식사 / 동반 인원) | 응답은 관리 화면(E23)으로 연결 |
| 기능 | 방명록 | 안내 문구 | 글은 관리 화면(E24)으로 연결 |
| 기능 | 계좌번호 | 계좌 여러 개(은행·번호·예금주), 복사 버튼 | 민감정보 처리 방식 미정(PLANNING §11) |

**블록이 아닌 "초대장 전체 설정"**: 색상 테마(B8), 기본 글꼴, 색상, **BGM**(초대장에 하나만 들어가므로 블록이 아님 — 확정)

## 4. 스타일 규칙 (확정)

- **B8 테마는 색상 테마**일 뿐, 글꼴과는 관계없음.
- **글꼴 크기는 서식별로 고정** — 사용자가 크기를 직접 조절하지 않음 → 결과물 품질 유지
- **기본 글꼴·색상은 에디터 첫 진입 단계(템플릿 선택 단계)에서 사용자가 직접 고름**
- 이후 **블록마다 글꼴·색상을 따로 바꿀 수 있음** — 언제든 "기본값으로 되돌리기"
- **색상은 팔레트 프리셋에서 선택** (자유 색상환 없음) — 결과물이 쉽게 망가지지 않도록

| 서식 | 용도 예시 | 크기(가안) |
|---|---|---|
| 제목1 | 표지 이름, 가장 큰 제목 (예: 신랑 ♥ 신부) | 30 |
| 제목2 | 섹션 제목 (예: 초대합니다, 오시는 길) | 22 |
| 제목3 | 소제목 (예: 신랑측, 신부측) | 18 |
| 본문1 | 기본 본문 (인사말 등) | 16 |
| 본문2 | 작은 글씨 (안내, 캡션) | 13.5 |

정확한 크기는 디자인 단계에서 확정.

## 5. 글꼴 후보 (시각 비교 후 결정)

**선정 조건**: 무료 상업적 이용 가능(SIL OFL), 한글 지원, 앱(에디터)과 웹(게스트 화면) 양쪽에서 쓸 수 있을 것 → Google Fonts 제공 폰트 위주.

**견본 페이지**: https://claude.ai/artifact/9wHHZrayUGp8M5KBvnjmU7 — 서식 5가지를 글꼴별/서식별로 비교, B8 색상 테마 배경으로 바꿔보기, 후보 표시 가능.

| 분류 | 글꼴 |
|---|---|
| 고딕 | Pretendard (앱 UI 글꼴), Noto Sans KR, 고운돋움, 나눔고딕 |
| 명조 | 나눔명조, 고운바탕, Noto Serif KR, 함렛, 송명 |
| 손글씨 | 나눔손글씨 펜, 나눔손글씨 붓, 개구, 하이멜로디 |
| 영문 포인트 | Playfair Display, Cormorant Garamond, Great Vibes (한글 글자 없음 — 날짜·이니셜 장식용) |

> 라이선스는 최종 확정 전에 각 배포처에서 다시 확인할 것.

**기술 메모**: 한글 폰트는 파일이 큼(Pretendard 굵기 하나에 약 2.7MB). 앱에 전부 내장하면 앱 용량이 크게 늘어나므로 → 앱은 **필요할 때 내려받기**, 게스트 웹은 **Google Fonts 웹폰트**(필요한 글자만 자동으로 잘라서 받음) 사용. 최종 목록은 6~8종, 굵기 1~2개로 최소화.

## 6. 에디터 첫 진입 (확정)

- 에디터에 **처음 들어올 때**(블록이 비어 있을 때) 시작 설정 단계:
  1. **빈 페이지로 시작 / 템플릿으로 시작** 선택
  2. **기본 글꼴** 선택
  3. **색상** 선택 (팔레트 프리셋)
- 템플릿을 고르면 B7에서 입력한 **호스트 이름·일시·장소를 블록에 자동으로 채움**
- 템플릿 = 기본 블록 조합. 예) 결혼식 기본형:
  `[이미지(커버)] [제목1: 신랑 ♥ 신부] [일시·D-day] [제목2 + 본문1: 인사말] [갤러리] [전화번호] [계좌번호] [RSVP] [방명록]`
- **실제 템플릿 콘텐츠는 엔진 완성 후 제작** — 그전까지는 "빈 페이지로 시작"만으로 개발·테스트
- 작성 도중 템플릿 다시 적용은 MVP에서 제외 — 기존 내용 덮어쓰기 위험

## 7. 에디터 메인(B9) 화면 구성

- **상단**: ← 나가기 / 초대장 제목 / [미리보기] / [전체 설정 ⚙] (기본 글꼴·색상·BGM)
- **탭**: [초대장] [감사페이지] — 감사페이지를 쓰는 경우에만 탭 노출. 간단모드면 별도 라이트 편집 화면
- **본문**: 블록 리스트 (표시 방식은 §11에서 결정)
- 블록 탭 → 선택 표시 + 편집 시트, 블록 메뉴(복제 · 삭제 · 위로 · 아래로)
- 블록 사이 `+` → **블록 추가 시트**(기본 / 연락·위치 / 기능 카테고리별)
- **순서 변경**: 길게 누르기 → 드래그
- **저장**: 자동 저장 (저장 위치는 §11에서 결정)

## 8. 데이터 구조 (개발 참고)

```ts
Invitation {
  colorThemeId: string                                            // B8 색상 테마
  style: { font: string; palette: string }                        // 첫 진입에서 고른 기본 글꼴·색상
  bgm?: { trackId, autoplay }
  pages: { invite: Block[]; thanks: Block[] }                     // 감사페이지 자유모드도 같은 Block[]
}

Block {
  id: string
  type: 'text' | 'image' | 'gallery' | 'divider' | 'spacer' | 'button'
      | 'map' | 'phone' | 'email'
      | 'datetime' | 'rsvp' | 'guestbook' | 'account'
  props: { ... }                                                  // 블록 종류별 내용
  style?: { font?, color?, align? }                               // 블록별 덮어쓰기 (없으면 기본값)
}
```

## 9. 기존 기획(PLANNING.md)과 달라지는 점

- **§3 블록 개념**: "인사말·호스트 정보·오시는 길" 같은 의미 단위 블록 → **기본 블록 조합으로 표현**하고, 그 조합은 템플릿이 제공
- **§5·§6 인트로 영상**: 제외 (동영상 블록 없음)
- **§10 가로 배열**: MVP는 **세로 배치만** — 가로 배열·좌우 비율 프리셋·구분자는 필요해지면 나중에 추가

이 기획안이 확정되면 PLANNING.md도 함께 고칠 예정.

## 10. 구현 단계

각 단계는 **와이어프레임 → 확인·수정 → 코드** 순서로 진행 (My Page와 동일한 방식).

1. **블록 엔진 기초** — 데이터 구조, 에디터 메인, 추가·삭제·순서 변경, 텍스트 블록(서식 5종), 기본 글꼴·색상 적용
2. **이미지·갤러리·구분선·여백·버튼**
3. **기능 블록** — 일시·D-day, 전화·이메일, 계좌번호, RSVP·방명록(에디터 배치까지; 실제 응답 수집은 게스트 화면(D)·관리 화면(E)과 함께)
4. **첫 진입 설정 화면 + 전체 설정** — 빈 페이지/템플릿 선택, 기본 글꼴·색상, 블록별 글꼴·색상 변경, BGM
5. **미리보기**, 감사페이지(자유모드 재사용 + 간단모드)
6. **템플릿 제작** — 완성된 엔진으로 행사 유형별 템플릿 추가

나중: 지도, 실제 저장(Supabase) 및 사진 업로드(Storage), 애니메이션 효과, 가로 배열
