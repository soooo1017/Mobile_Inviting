# 에디터(B9) 기획안 — 블록 에디터

> 상태: **v3 (2026-10-12) · 주요 결정 완료**
> 범위: IA 7~8번 — 에디터 메인(B9), 블록 편집, 이미지, BGM, 미리보기. 확정된 결정과 아직 정할 것(§11)을 구분해 적었습니다.

## 1. 핵심 방향 (확정)

- **커스터마이징(블록 조립)이 기본 엔진**이고, **템플릿은 그 블록들을 미리 배치해 둔 시작점(프리셋)**.
- 템플릿을 별도로 개발하지 않음 → 블록 엔진만 잘 만들면 템플릿은 데이터로 계속 추가할 수 있음.
- **엔진과 기능을 먼저 완성하고, 템플릿은 그 엔진을 활용해 나중에 만든다** (템플릿 개수도 그때 결정).
- 같은 엔진을 **감사페이지 자유모드**에서도 그대로 재사용.
- PLANNING.md §3의 셀링포인트("템플릿을 고르는 게 아니라 블록으로 조립한다")는 그대로 유지. 템플릿은 빈 화면에서 시작하는 부담을 덜어주는 출발점 역할.

## 2. 편집 방식 (확정)

- 화면에는 **블록들이 세로로 쌓인 리스트** — **세로 배치만 지원** (좌우로 나란히 놓는 가로 배열은 MVP에서 제외, 필요해지면 나중에 추가)
- 블록을 **탭하면 그 블록 전용 편집 시트/화면**이 열림 (텍스트면 서식+내용, 이미지면 사진 선택 등)
- **길게 눌러 순서 변경**, 블록 사이 **`+`로 추가**
- 노션처럼 문서 안에서 바로 타이핑하는 인라인 편집은 하지 않음 — React Native에는 웹의 `contentEditable`이 없어 구현 난이도가 매우 높고, 모바일에서는 블록 단위 편집이 더 편함

## 4. 스타일 규칙 (확정)

- **B8 테마 = 배경 색상 테마**. 지금 구조 그대로 유지하며, 글꼴과는 관계없음.
- **글씨 색은 사용자가 고르지 않음** — 배경 테마에 맞춰 자동으로 정해짐: 밝은 배경 5종(리넨·라벤더·블러시·가든·세이지)은 검정 계열, 어두운 **잉크** 테마는 흰색 계열. 첫 진입의 색상 선택, 블록별 색상 변경, 색상 팔레트는 모두 없앰.
- **글꼴 크기는 서식별로 고정** — 사용자가 크기를 직접 조절하지 않음 → 결과물 품질 유지
- **기본 글꼴은 하나** — 에디터 첫 진입 단계에서 사용자가 직접 고르고, 모든 서식에 적용
- 이후 **블록마다 글꼴을 따로 바꿀 수 있음** — 언제든 "기본 글꼴로 되돌리기"

| 서식 | 용도 예시 | 크기(가안) |
|---|---|---|
| 제목1 | 표지 이름, 가장 큰 제목 (예: 신랑 ♥ 신부) | 30 |
| 제목2 | 섹션 제목 (예: 초대합니다, 오시는 길) | 22 |
| 제목3 | 소제목 (예: 신랑측, 신부측) | 18 |
| 본문1 | 기본 본문 (인사말 등) | 16 |
| 본문2 | 작은 글씨 (안내, 캡션) | 13.5 |

정확한 크기는 디자인 단계에서 확정.

## 5. 글꼴 (확정 — 9종)

견본 페이지(https://claude.ai/artifact/9wHHZrayUGp8M5KBvnjmU7)에서 16종을 비교해 고름.

| 분류 | 글꼴 | 기본 글꼴로 선택 가능 |
|---|---|---|
| 고딕 | Pretendard | O |
| 고딕 | Noto Sans KR | O |
| 고딕 | 고운돋움 (Gowun Dodum) | O |
| 명조 | 나눔명조 (Nanum Myeongjo) | O |
| 명조 | Noto Serif KR | O |
| 손글씨 | 나눔손글씨 펜 (Nanum Pen Script) | O |
| 손글씨 | 하이멜로디 (Hi Melody) | O |
| 손글씨 | 개구 (Gaegu) | O |
| 영문 포인트 | Cormorant Garamond | X — 한글 글자가 없어 기본 글꼴로는 못 씀. 블록별 글꼴로만 선택(날짜·이니셜 등 영문 장식용) |

- 모두 SIL OFL(무료 상업적 이용 가능). 라이선스는 출시 전 각 배포처에서 다시 확인할 것.
- Pretendard 외 8종은 Google Fonts 제공 → 앱은 Expo용 Google Fonts 패키지, 게스트 웹은 Google Fonts 웹폰트로 같은 글꼴을 씀.

**기술 메모**: 한글 폰트는 파일이 큼(Pretendard 굵기 하나에 약 2.7MB). 앱에 전부 내장하면 앱 용량이 크게 늘어나므로 → 앱은 **필요할 때 내려받기**, 게스트 웹은 **Google Fonts 웹폰트**(필요한 글자만 자동으로 잘라서 받음) 사용. 굵기는 글꼴당 1~2개로 최소화.

## 6. 에디터 첫 진입 (확정)

- 에디터에 **처음 들어올 때**(블록이 비어 있을 때) 시작 설정 단계:
  1. **빈 페이지로 시작 / 템플릿으로 시작** 선택
  2. **기본 글꼴** 선택 (한글 글꼴 8종 중 하나)
- 템플릿을 고르면 B7에서 입력한 **호스트 이름·일시·장소를 블록에 자동으로 채움**
- 템플릿 = 기본 블록 조합. 예) 결혼식 기본형:
  `[이미지(커버)] [제목1: 신랑 ♥ 신부] [일시·D-day] [제목2 + 본문1: 인사말] [갤러리] [전화번호] [계좌번호] [RSVP] [방명록]`
- **실제 템플릿 콘텐츠는 엔진 완성 후 제작** — 그전까지는 "빈 페이지로 시작"만으로 개발·테스트
- 작성 도중 템플릿 다시 적용은 MVP에서 제외 — 기존 내용 덮어쓰기 위험

## 7. 에디터 메인(B9) 화면 구성

- **상단**: ← 나가기 / 초대장 제목 / [미리보기] / [전체 설정 ⚙] (기본 글꼴·BGM)
- **탭**: [초대장] [감사페이지] — 감사페이지를 쓰는 경우에만 탭 노출. 간단모드면 별도 라이트 편집 화면
- **보기 방식 토글 (확정)**: 내 초대장 목록(B6)의 보기 방식 토글처럼, 편집 화면에서 **[실제 모습] / [요약 카드]** 중 골라서 편집
  - **실제 모습**: 배경 테마·글꼴·사진이 적용된 완성본 모습 그대로 편집. 미리보기를 안 눌러도 결과가 보임
  - **요약 카드**: 블록마다 "텍스트 · 제목2 · 소중한 분들을 초대합니다" 같은 한 줄 카드. 전체 구성을 한눈에 보고 순서 바꾸기 쉬움
  - 마지막으로 고른 보기 방식을 기억
- 블록 탭 → 선택 표시 + 편집 시트, 블록 메뉴(복제 · 삭제 · 위로 · 아래로)
- 블록 사이 `+` → **블록 추가 시트**(기본 / 연락·위치 / 기능 카테고리별)
- **순서 변경 (확정)**: 길게 누르기 → 드래그. **실제 모습 보기에서 길게 누르면 모든 블록이 요약 카드로 접힌 뒤** 드래그하고, 손을 떼면 다시 실제 모습으로 돌아옴
- **저장 (확정)**: 자동 저장, **목업 단계에서는 폰 안에 저장**(§10 참고)

## 8. 데이터 구조 (개발 참고)

```ts
Invitation {
  themeId: string                                                 // B8 배경 색상 테마 (글씨 색도 여기서 결정)
  font: FontId                                                    // 첫 진입에서 고른 기본 글꼴 (한글 8종 중 하나)
  bgm?: { trackId, autoplay }
  pages: { invite: Block[]; thanks: Block[] }                     // 감사페이지 자유모드도 같은 Block[]
}

Block {
  id: string
  type: 'text' | 'image' | 'gallery' | 'divider' | 'spacer' | 'button'
      | 'map' | 'phone' | 'email'
      | 'datetime' | 'rsvp' | 'guestbook' | 'account'
  props: { ... }                                                  // 블록 종류별 내용
  style?: { font?: FontId; align? }                               // 블록별 덮어쓰기 (없으면 기본 글꼴)
}

       | 'nanumPen' | 'hiMelody' | 'gaegu' | 'cormorant'          // cormorant는 블록별로만
```

## 9. 기존 기획(PLANNING.md)과 달라지는 점

- **§3 블록 개념**: "인사말·호스트 정보·오시는 길" 같은 의미 단위 블록 → **기본 블록 조합으로 표현**하고, 그 조합은 템플릿이 제공
- **§5·§6 인트로 영상**: 제외 (동영상 블록 없음)
- **§10 가로 배열**: MVP는 **세로 배치만** — 가로 배열·좌우 비율 프리셋·구분자는 필요해지면 나중에 추가

이 기획안이 확정되면 PLANNING.md도 함께 고칠 예정.

## 10. 구현 단계

각 단계는 **와이어프레임 → 확인·수정 → 코드** 순서로 진행 (My Page와 동일한 방식).

**저장 방식 (확정): 목업 먼저.** 블록 구조가 아직 바뀔 가능성이 크므로 처음엔 초대장 내용을 폰 안에만 저장하고, 엔진이 안정된 뒤 게스트 화면(D)을 만들 때 서버(Supabase) 저장을 한 번에 연결.

1. **블록 엔진 기초** — 데이터 구조, 에디터 메인(실제 모습 / 요약 카드 보기), 추가·삭제·순서 변경, 텍스트 블록(서식 5종), 기본 글꼴 적용
2. **이미지·갤러리·구분선·여백·버튼**
3. **기능 블록** — 일시·D-day, 전화·이메일, 계좌번호, RSVP·방명록(에디터 배치까지; 실제 응답 수집은 게스트 화면(D)·관리 화면(E)과 함께)
4. **첫 진입 설정 화면 + 전체 설정** — 빈 페이지/템플릿 선택, 기본 글꼴, 블록별 글꼴 변경, BGM
5. **미리보기**, 감사페이지(자유모드 재사용 + 간단모드)
6. **템플릿 제작** — 완성된 엔진으로 행사 유형별 템플릿 추가

나중: 지도, 실제 저장(Supabase) 및 사진 업로드(Storage), 애니메이션 효과, 가로 배열
