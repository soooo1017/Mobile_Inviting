# 스토어 출시 준비 (Google Play · App Store)

> 2026-11-08 정리. 스토어 정책은 자주 바뀌어요 — **제출하기 전에 각 스토어의 최신 안내를 한 번 더 확인**해요.
> 앱은 Expo(React Native) 하나의 코드로 두 스토어에 모두 낼 수 있어요. 빌드·제출은 EAS(`eas build`, `eas submit`)로 해서 Mac이 없어도 iOS 빌드가 돼요.

## 1. 한눈에 비교

| | Google Play (Android) | App Store (iOS) |
|---|---|---|
| 개발자 등록 | 1회 **$25** | 매년 **$99** (Apple Developer Program) |
| 본인 확인 | 신분증 확인 (개인) · 사업자는 D-U-N-S | Apple ID + 2단계 인증 (개인) · 사업자는 D-U-N-S |
| 빌드 파일 | **AAB** (`eas build -p android`) | **IPA** (`eas build -p ios`) → TestFlight |
| 앱 고유 ID | `android.package` (예: `kr.moiso.app`) | `ios.bundleIdentifier` (같은 값 권장) |
| 출시 전 테스트 | **개인 계정은 비공개 테스트: 12명 이상이 14일 연속 참여** 후에야 정식 출시 신청 가능 | TestFlight (필수 아님, 권장) |
| 심사 | 보통 수일 (첫 앱은 더 걸릴 수 있음) | 보통 1~2일 (반려되면 수정 후 재제출) |
| 서명 | Play 앱 서명 (EAS가 키 관리) | 인증서 · 프로파일 (EAS가 자동 관리) |
| 개인정보 | **데이터 보안(Data safety)** 양식 | **앱 개인정보(App Privacy)** 항목 |
| 연령 등급 | IARC 설문 | 연령 등급 설문 |
| 스크린샷 | 폰 2장 이상 | 6.9″(또는 6.5″) iPhone 필수, iPad 지원 시 iPad도 필수 |
| 그래픽 | 아이콘 512×512 · 대표 이미지 1024×500 | 아이콘 1024×1024 (투명 없음) |

## 2. 두 곳 모두 필요한 것

1. **개인정보처리방침 URL** — 앱 안에만 있으면 안 되고 **웹 주소**가 있어야 해요 (Vercel에 정적 페이지로 올리면 됨). 약관의 `[서비스명]` · `[회사]` · 시행일 · 보호책임자 빈칸을 먼저 채워요.
2. **계정 삭제** — 가입 기능이 있는 앱은 **앱 안에서 계정 삭제**가 되어야 해요. Google은 웹에서 삭제를 요청할 수 있는 URL도 요구해요.
3. **심사용 테스트 계정** — 로그인이 필요한 앱이라 심사팀이 쓸 이메일 · 비밀번호를 제출해요 (샘플 청첩장이 들어 있으면 좋아요).
4. **스토어 소개 자료** — 앱 이름 · 짧은 설명 · 긴 설명 · 스크린샷 · 아이콘 · 지원 연락처(이메일).
5. **소셜 로그인 설정** — 카카오 · 구글 · 애플 각각 앱 등록(번들 ID / 패키지명 / 서명 지문). 개발용과 출시용 키를 구분해요.

## 3. 이 앱에서 특히 챙길 것

- **Apple 로그인**: 카카오 · 구글 같은 소셜 로그인을 넣으면 iOS에서는 Apple 로그인도 함께 제공해야 해요 (심사 반려 단골 사유).
- **방명록 = 사용자 작성 콘텐츠**: 신고 · 차단(또는 삭제) 수단과 운영자 문의 창구가 있어야 해요 (Apple 1.2 · Google UGC 정책). 이미 있는 "문의 접수" · 방명록 삭제 기능을 심사 노트에 적어요.
- **내 음악 업로드**: 저작권 안내 · 약관 12조 ③ · 권리자 요청 시 삭제 절차를 설명할 수 있게 준비해요.
- **음원 출처 · 라이선스** 화면이 있어서 CC BY 표기 의무를 충족해요. 음원은 Supabase Storage에 올린 뒤에 출시해요.
- **앱 안 결제**: 나중에 유료(프리미엄·구독)를 넣으면 앱 안 디지털 상품은 **Apple IAP / Google Play Billing**을 써야 해요 (수수료 발생). 결제 모델은 출시 전에 정해요.
- **iPad**: `supportsTablet: true`라 iPad 스크린샷이 필요해요. 폰 전용으로 낼 거면 `false`로 바꾸면 준비가 줄어요.
- **권한 문구**: 사진첩 저장 등 권한 안내 문구(한국어)는 `app.json`에 이미 있어요. 쓰는 권한만 요청하는지 마지막에 점검해요.

## 4. 코드·설정에서 할 일 (`mobile/app.json`)

현재 없는 값들이에요 — 출시 전에 채워요.

- `ios.bundleIdentifier` · `android.package` (한 번 정하면 바꾸기 어려워요)
- `version` · `ios.buildNumber` · `android.versionCode` (제출할 때마다 올림. EAS `autoIncrement` 사용 가능)
- `ios.infoPlist.ITSAppUsesNonExemptEncryption: false` (암호화 수출 규정 질문 생략)
- 앱 아이콘 · 스플래시 · 안드로이드 적응형 아이콘 (지금은 기본 이미지, 적응형 배경색 `#E6F4FE`도 기본값)
- `eas.json` (development / preview / production 프로필)
- 딥링크 · 유니버설 링크가 필요하면 도메인 확정 후 설정

## 5. 순서대로 따라가기

1. **계정 만들기** — Google Play Console($25) · Apple Developer($99). 승인에 며칠 걸릴 수 있어 가장 먼저 시작해요.
2. 앱 ID · 앱 이름 · 도메인 확정 → `app.json` 채우기
3. 서버 연결(Supabase) · 음원 업로드 · 개인정보처리방침 웹 페이지 공개
4. `eas build` 로 Android · iOS 테스트 빌드 → 실제 폰에서 점검 (Expo Go와 다르게 동작하는 부분 확인)
5. **Android**: 비공개 테스트 트랙에 올리고 테스터 12명 모집 → 14일 유지 → 프로덕션 신청
6. **iOS**: TestFlight로 내부 테스트 → App Store Connect에 메타데이터 · 스크린샷 · 심사 노트 입력 → 심사 제출
7. 양쪽 심사 통과 → 출시 (단계적 출시 / 수동 출시 선택 가능)

> Android의 14일 대기 때문에 **Google Play를 먼저 시작**하는 게 일정상 유리해요. 테스터는 지인 · 하객 후보로 모아도 돼요.

## 6. Android · iOS 호환 메모

- 코드는 하나라서 두 플랫폼에서 모두 돌아가요. 키보드 · 날짜 선택기 · 탭바 그림자는 플랫폼별로 나눠 처리해 뒀고, 모든 모달은 Android 뒤로가기 버튼을 처리해요.
- 지금까지 기기 점검은 한 플랫폼(Expo Go) 위주라 **다른 플랫폼에서는 `DEVICE_CHECKLIST.md`를 처음부터 한 번 더** 돌려야 해요.
- 특히 Android에서 확인: 날짜 선택(대화상자 방식) · 키보드가 입력창을 가리는지 · 뒤로가기 · 하단 시스템 바(화면 끝까지 그려지는 방식) 안전 영역 · 배경음악 속도 조절 · 사진첩 저장 권한.
- 특히 iOS에서 확인: 무음 모드에서 미리 듣기 · 노치/홈 인디케이터 안전 영역 · 인라인 날짜 선택기.
