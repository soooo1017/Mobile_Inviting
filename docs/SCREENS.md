# 앱 화면 구성 (정보구조 / IA)

> `PLANNING.md`에서 논의된 기능을 바탕으로 필요한 화면을 카테고리별로 정리한 문서입니다.
> 결혼식에 국한하지 않고 모든 행사(결혼식·돌잔치·생일파티·집들이 등)의 초대장을 다루므로, 화면/용어도 "초대장"·"행사"·"게스트" 기준으로 일반화했습니다. 행사 유형별로 화면이 갈라지지는 않으며, 프로젝트 생성 시 행사 유형을 선택하고 문구는 사용자가 자유롭게 채웁니다.
>
> 디자인 핸드오프가 들어온 화면은 코드(React Native/Expo, `mobile/`)로 구현을 마쳤고 상태를 **✅ 구현됨**으로 표시합니다. 나머지는 아직 디자인 전이라 기능 명세만 있거나(B6 상세 스펙처럼) 자리만 잡아둔 상태입니다.

## A. 앱 공통 / 기본 구성 — ✅ 구현됨 (A1–A7)

> **✅ 로그인 인증 실제 구현됨**: 데이터 백엔드는 Supabase(Postgres + Auth)를 사용. 로그인 아이디는 이메일이 아니라 **사용자가 정한 아이디**이며, 이메일은 가입 인증 용도로만 쓴다 — 아이디→가입 이메일을 서버 쪽 RPC로 조회한 뒤 내부적으로 이메일/비밀번호 로그인을 수행. 아이디는 대소문자 구분 없이 DB에서 유니크(중복 가입 불가, 실시간 중복확인), 닉네임은 표시 전용이라 중복 허용. 비밀번호는 Supabase가 해시로만 저장하고 평문은 어디에도 남지 않음. 자세한 스키마는 `supabase/schema.sql` 참고.

## B. 제작 흐름 (로그인 후 — 프로젝트/에디터)

**진입 순서 확정**: 프로젝트 생성(B7) → 스타일 테마 선택(B8) → 에디터 메인(B9)

**탐색 구조**: 로그인 후에는 실제 하단 탭 내비게이션(`MainTabs`)으로 진입합니다. `@react-navigation/bottom-tabs` 기반의 진짜 탭 네비게이터입니다.

**✅ 탭 2개로 축소 + 가운데 버튼(변경됨)**: 기존 "홈 · 내 초대장 · 마이" 3탭 구조에서, 대시보드였던 "홈"을 없애고 **"홈 · My Page" 2탭**으로 줄였다 — "홈" 탭이 바로 B6(내 초대장 목록) 화면이다. 두 탭 사이 가운데에 다른 탭과 동일한 크기·색으로(튀지 않게) 배치된 **원형 + 버튼**이 있고, 누르면 바로 B7a(새 초대장 만들기 1단계)로 이동한다.

**프로젝트 목록 카드 구조**: 각 초대장 카드에 **[편집] [관리]** 2개 버튼이 함께 노출됨 — 에디터는 순수 콘텐츠 편집 전용, 관리는 응답/방명록/통계/프로젝트 설정 전용으로 역할 분리.

**에디터 내부는 편집 대상에 따라 2가지로 나뉨**:
- **초대장 편집**: 기존 블록 에디터로 편집
- **감사페이지 편집**: 관리 화면에서 설정한 감사페이지 모드에 따라 분기
  - 자유 모드 → 초대장과 **동일한 블록 에디터 재사용** (편집 대상만 감사페이지로 전환)
  - 간단 모드 → 고정 레이아웃의 **별도 라이트 편집 화면** (문구+사진 정도만 교체)

### B6 프로젝트 목록 화면 상세 — 검색 · 필터 · 정렬 · 보기 방식

디자인 핸드오프(`docs/design/B-project/README.md`, 스크린샷 코드 B6b–B6w, B7f)를 그대로 구현했습니다. 아래는 확정된 동작 명세입니다.

#### 1. 검색 (B6e)
- 대상: 프로젝트명(초대장 제목), 부분 일치
- 입력하는 대로 실시간으로 목록이 좁혀짐, 별도 검색 버튼 없음
- 검색어가 비어 있으면 전체 목록 노출
- 키보드 `검색` 키 표시. 목록 빈 곳을 누르거나 스크롤하면 키보드가 닫힘(아래 G '입력 화면 공통 동작')

#### 2. 필터 (B6f)
- **초대장 상태**: 전체 · 작성중 · 공유중 · 감사 페이지 · 지난 행사 (전체는 단독 선택, 나머지는 다중 선택 가능 — 하나라도 고르면 전체는 해제)
- **행사 월**: 연도 이동 가능, 1~12월 중 다중 선택
- **행사 종류**: 8개 카테고리(결혼식·돌잔치·백일·생일파티·집들이·개업식·동창회·기타) 다중 선택
- **장소 지역(시도)**: 17개 광역시도, 다중 선택
- 카테고리 내부는 OR, 카테고리 간에는 AND로 결합 — **확정**
- 적용된 필터 개수를 [필터] 버튼에 뱃지로 표시, 하단 고정 바에 [초기화] + [결과 N개 보기]
- UI는 화면 3/4 높이의 바텀시트

#### 3. 정렬 (B6g, 단일 선택)
- **최근 수정순 — 기본값(확정)**: 방금 작업하던 프로젝트가 맨 위로 오는 "이어서 작업하기" 시나리오
- **최근 행사순**: 행사일이 늦은(가까운 미래부터 먼 미래까지, 내림차순이 아니라 **최신 날짜가 먼저 오는 순서**) 순서 — ⚠️ 이전 버전 문서에 "행사일이 가까운 순"이라고 잘못 적혀 있었음. 디자인 핸드오프 기준 정확한 정의는 **행사일 내림차순(날짜가 늦은 것부터)** 이다.
- **오래된 행사순**: 행사일 오름차순(날짜가 빠른 것부터)
- **최근 만든순**: 생성일(createdAt) 내림차순
- **이름순**: 가나다 · ABC
- 한 번에 하나만 선택, 고르면 바로 시트가 닫힘

#### 4. 보기 방식 (3종, 토글)
프로젝트 카드마다 [편집]/[관리] 진입은 모든 보기 방식에서 "카드 탭 → 액션 시트"로 통일됩니다(개별 버튼 아님). 마지막으로 선택한 보기 방식은 기기에 저장되어 기억됩니다.

**✅ 토글 아이콘 교체(변경됨)**: 기존엔 유니코드 특수문자(▤▦≡)를 텍스트로 그려서 플랫폼에 따라 모양이 뭉개지고 구분이 잘 안 됐음 → 전용 SVG 아이콘(카드 2개=상세, 2x2 격자=썸네일, 가로줄 3개=리스트)으로 교체. 터치 영역도 28×28 → 36×36으로 확대.

#### 5. 카드 탭 → 액션 시트 (B6s / B6t) — ✅ 수정 반영됨
- 상단: 상태칩 · 유형 · D-day · 제목
- 2분할 큰 버튼: **[편집]**(→ B9) / **[관리]**(→ E21)
- **감사 페이지 설정 박스**: 상태와 무관하게 **항상 노출**(확정). 설정됨(B6s, 기간 표시) / 미설정(B6t, 안내 문구) — 버튼은 **[감사 페이지 편집] 하나만** 노출(→ B9 감사페이지 탭). 기간 변경·설정도 전부 거기서 한다 — 액션 시트에는 기간 버튼이 없음(확정, 핸드오프 #4).
- 메뉴: 미리보기 · 공유 링크 복사
- 구분선 뒤 **삭제하기**(→ 삭제 다이얼로그)
- ⚠️ 이전 버전 문서에는 B6j(기본, 감사 페이지 박스 없음)와 B6s/B6t(감사 설정됨/미설정)를 서로 다른 3가지 상태로 다루고, 메뉴에 "이름 바꾸기 · 복제하기"가 있었음. 최신 디자인 핸드오프에서 B6j가 폐기되고 B6s/B6t 둘로 통합되었고(감사 페이지 박스 항상 노출), 메뉴에서 이름 바꾸기·복제하기가 빠졌습니다. 코드도 함께 반영: `RenameDialog` 제거, `ProjectsContext`의 `renameProject`/`duplicateProject` 제거.
- ⚠️ **핸드오프 #4**: 감사 페이지 설정 박스의 [기간 변경]/[기간 설정] 버튼이 삭제됨(기간 설정은 B9 감사페이지 탭으로 이관). 코드도 함께 반영: `onThanksPeriod` prop과 `PeriodSheet` 컴포넌트 제거.

#### 6. 삭제 (B6l / B6m / B6n / B6o) + 데이터 내려받기 (B6u / B6u0 / B6u2 / B6u3 / B6v / B6w) — ✅ 핸드오프 #4 반영됨
- **작성중(공유 전)**: 단순 확인 다이얼로그(`'{title}'을 삭제할까요?`)
- **공유중 이상**: 경고 문구 + 정보 박스(초대장 이름/공유 링크/RSVP·방명록 삭제 건수) + **"데이터 내려받기"** 링크(→ 아래 내려받기 시트) + 체크박스로 확인해야 [삭제하기] 활성화. 체크 표시는 삭제 맥락이라 선택색 대신 **`--error`(붉은색) 배경 + 흰 ✓**.
  - 내려받기를 완료하면 링크 문구가 `✓ 내려받기 완료 · 다시 내려받기`로 바뀜(다시 눌러서 재내려받기 가능).
- **데이터 내려받기 시트** (삭제 다이얼로그 위에 겹쳐 뜨는 2단계 바텀시트):
  1. **항목 선택 (B6u)**: 초대장 / 감사 페이지(감사 페이지 미설정 초대장이면 항목 자체를 숨김) / RSVP 응답 / 방명록 체크 4종. 하나도 체크하지 않으면 [다음] 비활성(B6u0).
  2. **파일 형식 (B6u2/B6u3)**: 1단계 선택에 따라 그룹을 조건부 표시 — 초대장·감사 페이지 선택 시 이미지(.png)/PDF(.pdf) 단일 선택, RSVP·방명록 선택 시 엑셀(.xlsx)/CSV(.csv) 단일 선택. ZIP 파일명(`{title}_{YYYY-MM-DD}.zip`) + 포함 파일 목록 미리보기. [다운로드] 하나.
  - **[단순화]** B6v(OS 공유 창, `UIActivityViewController`/`Intent.ACTION_SEND`)는 구현하지 않음 — 이 앱은 목업 데이터만 다루고 실제 내보내기/백엔드가 없어서 공유할 실제 파일이 없음. [다운로드]를 누르면 바로 B6w 완료 상태로 전환된다.
  - **완료 (B6w)**: 삭제 다이얼로그로 복귀, 하단에 초록 토스트 `데이터를 내려받았어요` + 우측 `열기` 링크(3초, 탭하면 "다음 핸드오프에서 제공됩니다" 안내).
- 완료 시 토스트 노출(`'{title}'을 삭제했어요`, 3초), 휴지통/되돌리기 없음 — 즉시 영구 삭제(확정)

#### 조합 동작 / 데이터 모델
- 검색 → 필터 → 정렬 순으로 적용 (동시 사용 가능)
- 결과가 0건이면 B6i 빈 상태(`조건에 맞는 초대장이 없어요`) + [필터 초기화]
- 데이터 모델은 `mobile/src/types/project.ts`에 구현: `Project { id, title, eventType, customTypeName?, hosts, eventAt, venue?, thanks:{enabled, days?, hasContent}, shared, themeId, updatedAt, createdAt, counts:{rsvp, guestbook} }`
- 상태 파생 규칙(`mobile/src/utils/projectStatus.ts`에 구현, 확정):
  1. `!shared` → 작성중
  2. `shared && now < thanksStart` → 공유중 (`thanksStart` = 행사 다음 날 00:00)
  3. `thanks.enabled && thanksStart ≤ now ≤ thanksEnd` → 감사 페이지 (`thanksEnd` = `thanksStart + days - 1`, 23:59:59)
  4. 그 외 → 지난 행사 (감사 페이지 미설정이면 행사 다음 날부터 링크 접속 불가)

### 입력 화면 공통 동작 — ✅ 구현됨 (`KeyboardAwareForm`)

입력란이 있는 모든 화면(로그인 · 회원가입 · 비밀번호 찾기 · 닉네임 변경 · 비밀번호 변경 · 회원 탈퇴 · 문의하기 · 새 초대장 1/4·2/4 · 내 초대장 검색)에 똑같이 적용한다.

- **키보드에 가리지 않기**: 키보드가 올라오면 화면이 줄어들고, 지금 입력 중인 칸이 키보드 위로 보이도록 자동 스크롤.
- **하단 고정 버튼**(새 초대장 마법사의 `다음` 등)은 키보드 바로 위로 함께 올라온다.
- **키보드 닫기**: 버튼·입력란이 아닌 곳(글자, 여백, 빈 공간)을 누르거나 화면을 아래로 끌면 키보드가 닫힌다. 키보드가 떠 있어도 버튼·다른 입력란은 한 번에 눌린다.
- **이메일 입력란**(회원가입 · 비밀번호 찾기): `@` 앞을 입력하면 자주 쓰는 도메인(naver.com · gmail.com · daum.net · hanmail.net · kakao.com · nate.com · icloud.com)을 칩으로 제안, 누르면 자동 완성. `@` 뒤를 입력하면 맞는 도메인만 남는다.
- Expo Go에서 바로 동작하도록 별도 네이티브 라이브러리 없이 RN 기본 `KeyboardAvoidingView` + `ScrollView`로 구현.

## 화면 흐름 다이어그램

디자인이 아니라 "어떤 동작을 하면 어떤 화면으로 이동하는지"만 표현한 흐름도입니다. 점선(`-.->`)은 자동 전환/링크 전달처럼 사용자의 직접 탭이 아닌 흐름입니다. 에러/빈 상태 화면(G)은 특정 상황에서 조건부로 뜨는 공통 화면이라 흐름도에는 표시하지 않았습니다.
